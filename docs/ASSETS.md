# DiOffice Asset Guide v0.1

## Goal

Use free/legal starter assets to validate the product quickly while keeping a clean path toward original DiOffice art.

## Art direction

- Chibi pixel software office
- Cozy RPG-like office atmosphere
- Original DiOffice identity over time
- Do not copy proprietary MapleStory characters, maps, sprites, or UI

## Current original side-view studio assets

| File in `apps/web/public/art/` | Logical size | Use |
|---|---|---|
| `studio-world.png` | 640×360 RGB | Original main-office forest/cottage scene |
| `studio-world-garden.png` | 640×360 RGB | Original garden zone adjoining the main office |
| `studio-world-workshop.png` | 640×360 RGB | Original workshop zone adjoining the garden |
| `studio-engineer-idle.png` | 40×56 RGBA | Shared original engineer idle avatar and UI portraits |
| `studio-owner-idle.png` | 40×56 RGBA | Human Owner avatar and lower HUD portrait |
| `studio-owner-walk.png` | 160×56 RGBA | Four adjacent 40×56 Owner walking frames |
| `studio-owner-states.png` | 160×168 RGBA | Four-frame idle, jump/fall, and landing/recovery animation rows |

The original woodland assets are programmatic pixel illustrations: the first five are generated by `tools/art/generate-studio-art.py`; the garden/workshop scenes and Owner animation sheets are generated by `tools/art/generate-studio-world-expansion.py` (seed `738214`). They are not external MapleStory art or modified proprietary sprites. Provenance is recorded in `apps/web/public/art/README.md`; the existing CC0 2dPig attribution/license is preserved.

Idle sprites use 40×56 frames; the walk sheet is a horizontal 160×56 strip, while the 160×168 state sheet has four-frame idle, jump/fall, and landing/recovery rows. Both sheets use binary alpha; grounded frames share a foot baseline. Animate and mirror only the local Owner; reduced-motion preferences suppress looping animation. The 1,920×360 world is three adjacent 640×360 original scenes with one shared ground plane; the small route map marks the current local Owner position. Landing platforms and solid obstacles are logical collision geometry, not physics inferred from image pixels. Do not treat an idle pose as proof an agent is idle, typing or running: visible employee status comes from the API. The human Owner moves only on local input, never as automatic agent execution.

The world camera follows local movement and clamps to world bounds. The Owner animation selector distinguishes idle, walk, jump, fall, and landing while remaining purely visual; reduced-motion preferences disable animation. The world is a side-view navigation toy, not a complete platformer or employee simulation. Its viewport scale need not be integer; retain nearest-neighbor rendering, aligned feet/ground plane, and nameplates that remain fully readable on narrow screens. Do not embed UI labels, employee identities, task progress, HP/XP or fake runtime statistics into image pixels. A permanent per-employee animation manifest and richer platform-game physics remain future scope.

## Logical grid

Primary logical tile grid: 16x16 px.

Use integer display scaling where possible.

## Starter asset strategy

### Core office pack

2D Pig Pixel Office

Use for prototype office environment, furniture, computers, and visual references.

License baseline recorded for starter bundle: CC0/public domain.

### Supplementary CC0 assets

Only include third-party assets in the repository when redistribution terms are clear.

Assets that are free-to-use but unclear about redistribution should remain source links only until license verification is complete.

## Asset provenance

Every externally sourced asset should record:
- asset name
- source URL
- creator
- license
- source filename
- local filename
- modification notes
- checksum where useful

## Asset manifest contract

Game logic should refer to stable asset IDs, not hard-coded source filenames.

Example conceptual record:

```json
{
  "id": "office-desk-basic-01",
  "type": "desk",
  "gridWidth": 2,
  "gridHeight": 2,
  "source": "2dpig-pixel-office",
  "sprite": "processed/furniture/desk-basic-01.png"
}
```

## Character contract

Each permanent employee eventually needs a consistent sprite definition:
- idle
- walk directions
- seated
- typing
- thinking
- talking
- success

MVP can use a simplified set while keeping the manifest future-compatible.

## Monitor states

At minimum:
- off
- terminal
- code
- browser
- testing
- warning/approval

The pixel monitor is a status visualization. Detailed terminal/code/browser content belongs to the React Workstation UI.

## Asset generation later

Frontend/design employees may eventually create or request assets through an Asset Service.

Generated assets must pass:
- size/grid validation
- transparency validation
- style consistency check
- manifest generation
- provenance metadata

## Production direction

Free assets are for MVP acceleration. Deni, Nabil, Raka, signature office props, and major rooms should eventually become original DiOffice IP.
